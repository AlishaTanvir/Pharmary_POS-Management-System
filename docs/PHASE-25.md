## Implemented controls

The Windows package now has a versioned v2 integrity manifest and release-policy inventory, recording migration hashes, tested Node major 24, PostgreSQL major 18 and PKR. A dependency-free verifier checks every listed file hash, exact inventory, required entry points, browser assets, matching version/policy and migration inventory/checksums. It refuses traversal, absolute/ambiguous Windows paths, duplicate case-insensitive paths, links and unexpected/private files. An installed program may additionally contain only its existing data-location.txt pointer. This pointer is runtime configuration and is not authenticated by the manifest.

Packaging self-verifies before a candidate is qualified. Install verifies before creating a program directory or touching private data. The supervisor verifies the installed program before reading private configuration or importing production dependencies. Its private .env is authoritative over inherited shell variables, preserving installed port/key/database identity. Existing frozen Phase 5 artifacts are unchanged. These unsigned hashes detect accidental changes; anyone able to replace the verifier/manifest can replace the evidence. They do not authenticate a publisher or replace signing and trusted delivery.

Migration startup now rejects unknown applied migration names and non-prefix migration history under the existing advisory lock. Rechecks before each applied migration serialize with other supported migrators. This prevents a guarded release from automatically starting against a newer or inconsistent schema. It does not undo migrations, compare historical SQL hashes stored in older databases, prove semantic compatibility, or retrofit guards into old frozen binaries. Side-by-side rollback still requires reviewed schema/policy compatibility and independently verified recovery evidence.

## Repeatable acceptance and CI

npm run test:acceptance starts an independently named persistent PostgreSQL cluster on port 55525, creates an independent database, counter store and backup directory, and generates temporary database/owner/cashier/backup/control secrets in memory. It does not use the operator database connection or account secrets. It retains the pre-capture legacy fixture and the 105-medicine/505-customer scale fixture. The real outage journey is parameterized to stop/restart this owned acceptance cluster, rather than the development cluster. API and PostgreSQL are stopped after verification. Port 3001 must be free; the runner refuses an occupied API port before starting. Persistent test files remain private under ignored directories, including the cluster's authentication material; they must never be published.

The Windows CI workflow runs build/backend checks, installs PostgreSQL backup utilities only after matching the recorded SHA-256 archive checksum, runs the full Chromium acceptance and a separate Firefox smoke journey, and builds a self-verified unsigned package. Only the credential-free summary and allowlisted unsigned package are configured as artifacts; private databases/stores, backup keys, .env and initial credentials are excluded. A CI workflow definition is not evidence that hosted jobs ran. Firefox smoke coverage is not full Firefox acceptance or Safari/Windows-version certification.
