# Phase 17 - automatic online cart recovery

Authorized as the next sequential phase after Phase 16. Source: 0.17.0-dev.1. Verification date: 22 November 2026. Status: software complete; field acceptance and production approval remain pending.

## Recovery workflow

Online checkout now saves unsuspended drafts automatically, 600 ms after basket or supporting-field changes settle. The Point of sale recovery notice reports saving, saved and failure states. Wait for Recovery draft saved before reloading; unsaved changes within the debounce window or a failed request cannot be promised durable. This is not a physical power-loss or device acceptance claim.

Reloading the same browser tab under the same authenticated cashier and selected branch offers Recover online cart or Discard recovery draft. The checkout controls remain disabled until the choice is resolved. Recovery reloads current active medicines, pack units, prices and saleable stock, retaining quantity, discount, customer, sale notes, prescription reference, saved-cart label and any linked suspended-cart reference. Stock, discounts, tax, restricted-sale policy and payment are rechecked during checkout. Inactive/missing items or customers block recovery without deleting the saved draft; discard allows starting again.

Drafts reserve no stock and post no payments, invoices, movements or balances. Payment tenders, external payment references, passwords and supervisor approval tokens are not persisted in the recovery payload. A recovered restricted/discount basket needs authorization under the current policy. Existing suspended carts remain a separate explicit workflow.

Draft contents live in PostgreSQL. Browser session storage holds only an opaque UUID under a cashier/branch-scoped key; it does not hold medicine details, notes or customer data for this feature. Ordinary same-tab reload is supported. Closing a tab, clearing session storage, changing browsers/devices or browser crash-restoration policies can lose that reference. If session storage is unavailable, the UI warns that automatic recovery is unavailable and the existing explicit Suspend cart workflow remains available. This is not cross-device cart synchronization.

Sign-out, detected authentication expiry and the client idle lock forget this tab's recovery references and clear the live workspace. A subsequent login does not automatically expose the previous session's draft. Server records remain permission-protected until expiration/cleanup; forgetting a reference is not secure erasure of its database contents. Drafts expire 24 hours after their last changed save. Expired records for the authenticated cashier/branch are purged during subsequent draft operations. Backups may retain their original contents. Up to 20 live recovery drafts per cashier/branch are allowed; forgotten references can occupy that quota until expiry.

## Checkout outcome and concurrency

The recovery state retains the basket's checkout idempotency key. Before offering recovery, and before reviewing, posting or suspending the current basket, the service checks whether that key already produced an invoice or explicit saved cart. Its lookup shares the sale posting advisory lock, so it waits for an in-flight posting to finish. An already-posted checkout offers Open posted invoice, which uses the existing duplicate-receipt view, instead of restoring a basket for a second sale. A completed suspension directs the user to Saved carts. The browser test deliberately drops a successful checkout response, attempts suspension, reloads and verifies one invoice and one stock deduction.

Checkout controls freeze while a request is in progress. Successful posting/suspension clears the recovery draft and rotates the browser reference. Discard also clears the live basket and its metadata before enabling a new sale. If cleanup fails after a successful sale, the retained checkout key still allows the recovery lookup to recognize the posted outcome. No financial posting service or request-hash policy is relaxed.

Draft writes use revisions, a state hash and cashier/branch plus draft advisory locks. A repeated unchanged save is accepted even when its response was lost. Competing changed writes with an old revision are rejected. Clearing writes a content-free tombstone so a delayed request cannot resurrect the old basket. Browser tabs that clone the same session-storage reference may conflict; the UI reports the failure. Use Keep this cart separately to save local edits under a new recovery reference without overwriting the other copy, or reload to review the saved version. No last-writer-wins merge is implied.

## Schema, API and audit

Migration 015 adds online_cart_drafts with selected branch, cashier, revision, bounded state, request hash, discarded flag and update time. The normal migration launcher applies it; the frozen Phase 5 archive is unchanged. The table is transient mutable state, separate from immutable posted history.

All /api/online-drafts/:id operations require sales-write permission and the selected cashier/branch scope. Writes require the existing CSRF/session controls. GET returns the draft or null; foreign-owner/branch identifiers return 404. PUT accepts {revision,state}; the strict state contains cart, label and saved_cart_id, with at most 100 lines and existing quantity/money/note bounds. The cart permits zero lines for notes-only drafts and excludes payments and approval_id. POST /restore validates the expected revision and rehydrates current data. DELETE accepts the expected revision and clears the payload. Revision or unavailable-item conflicts return 409; invalid input returns 400.

ONLINE_DRAFT_RECOVERED and ONLINE_DRAFT_CLEARED record the actor/branch and operation; recovery includes line count and revision. Autosaves do not append private cart content to the audit stream on every keystroke. Server-side state and backups remain subject to the established deployment/storage controls. Autosave runs only on changes, so it is not a periodic session keepalive; the existing activity/idle controls remain.

## Handoff and remaining work

Use the Point of sale notice to confirm durability and to recover or discard a draft after reload. Review current prices and payment again. Use Sales history or Open posted invoice when a checkout outcome is uncertain; do not re-enter it as a new sale. Explicitly suspended carts remain the durable user-managed list for later retrieval beyond a browser tab reference.

This closes the bounded online unsuspended-cart reload gap, not every device/browser/power-loss scenario in NFR-05. Prepared offline checkout and its SQLite journal are unchanged. Historical category reconstruction, purchase invoice tax/discount accounting, opening balances, bank reconciliation, multi-currency and other matrix gaps remain separate work. Physical printer/scanner and off-device recovery acceptance remain user-deferred. Operator acceptance and production approval remain pending. Phase 18 has not started.
